0. The big picture

One sentence: the sampler lives in a single-plane world (flat parameter names, one flat kwargs_lens list, one kwargs_source, one sampled D_dt); the module alpaca/models/multiplane.py is a bidirectional dictionary that, on every likelihood call, unfolds that flat world into herculens' per-plane multi-plane language, lets herculens do genuine multi-plane ray tracing, and folds the result back into single-plane shape. Nothing physical is single-plane — only the data format at the boundary is.

 sampler / prob_model / plotting / postprocess          (flat, "single-plane-shaped")
 ─────────────────────┬──────────────────────────────────────────────────────────────
                      │  kwargs_lens=[EPL, SHEAR, SIS]   kwargs_source=[...]   D_dt
                      ▼
 MPLensImageAdapter  +  MPMassModelFacade              (ALPACA: translation only)
                      │  split_kwargs → [[EPL', SHEAR'], [SIS]]   eta_flat   k_planes
                      ▼
 MPLensImageWithPSF                                     (ALPACA: 2 overridden methods)
                      │
 ─────────────────────┼──────────────────────────────────────────────────────────────
                      ▼
 herculens MPLensImage / MPMassModel / MPLightModel / MPPointSourceModel
                        (upstream: ALL the physics — eta recursion, rendering)

Who owns what:

ComponentOwnerJob
MPMassModel.ray_shooting, eta matrix, per-plane deflections/potentials herculensthe multi-plane physics (recursion x_j = x_1 − Σ η_ij α_i(x_i))
MPLensImage internals (Grid, Numerics, convolution, adaptive source grid) herculensimage rendering
MPGeometry, build_plane_structure, build_mp_geometry ALPACAstatic plane bookkeeping + fiducial-cosmology constants
MPMassModelFacade ALPACAflat↔per-plane kwargs, convention rescaling, effective Fermat potential
MPLensImageWithPSF ALPACAsubclass fixing two upstream gaps (live-PSF hook, plane-selective light eval)
MPLensImageAdapter ALPACApresents LensImage.model()'s exact call surface over the MP stack

Why this design? Every consumer in ALPACA — four sampler backends (NUTS, NIFTy, nautilus, gradient descent), joint-PSF fitting, blinding, postprocessing, all plotting — speaks the single-plane dialect. The adapter approach let multi-plane land without touching any of them (there are only 7 is_multiplane branch sites in the whole codebase, nearly all in plotting). The trade-off: the design is invisible from above, which is exactly why it can be hard to see "where multi-plane happens". Answer: entirely inside multiplane.py.

1. End-to-end data flow — HE 0435−1223 with one perturber

Concrete system: main deflector at zl = 0.4546, source at zs = 1.6926, θE ≈ 1.18″, plus one catalog perturber at z = 0.78 with SIS θE = 0.1″. All numbers below were computed with the actual ALPACA/herculens code (fiducial H0 = 70, Ωm = 0.3).

  1. Config & catalog. model.perturbers.path points to the perturber-finder JSON. perturber_inputs_from_config (perturbers.py:325) parses config knobs; load_perturber_set parses the JSON. Fiducial cosmology from default_config.py: PERTURBERS_H0_FID = 70.0, PERTURBERS_OM0 = 0.3.
  2. Plane assignment. prepare_perturbers (perturbers.py:220): since 0.4546 < 0.78 < 1.6926 and |z − zl| > z_tolerance (0.01), the perturber gets plane = "background". Its RA/Dec is converted to ALPACA's centered arcsec frame. This one tag is the entire trigger for multi-plane mode. (With mode="single_plane" it would be forced to "main" and everything below is skipped — plain single-plane model with one extra SIS.)
  3. Model construction. make_lens_image (prob_model.py:221) sees an off-plane perturber at line 403 and calls make_mp_lens_image (multiplane.py:595), which builds the static geometry: 
    plane_redshifts = [0.4546, 0.78]      main_plane_index = 0
plane_slots     = [[0, 1], [2]]       # flat kwargs slots per plane
profile_lists   = [["EPL","SHEAR"], ["SIS"]]
eta(main→src)   = 1.732               defl_scales = [0.577, 1.0]
TD prefactors   = [133.7, 182.7] days D_dt_fid = 2757 Mpc  (·TD_CONST = 77.2 d/arcsec²)
    All of this is frozen — the sampler never touches it.
  4. Sampling. The sampler proposes flat sites, identical naming to a single-plane run plus one extra: lens_theta_E, lens_gamma, …, lens_gamma1/2, pert5_theta_E, D_dt, …. ProbModel.model() / params2kwargs() assemble the flat kwargs_lens = [EPL, SHEAR, SIS] via the shared helpers.
  5. Unfold (every likelihood call). MPMassModelFacade.split_kwargs deals the flat list per plane and rescales into herculens' convention: θE = 1.18″ → 0.68″ for the EPL (× 0.5771/(γ−1)), shear × 0.577; the SIS passes through (scale 1.0). The rescale and herculens' η = 1.732 cancel exactly, so parameters keep their standard source-referenced meaning.
  6. Multi-plane ray shooting (herculens). A ray from image position (1.30″, 0.30″) travels: 
    z=0      (+1.3000, +0.3000)  → deflected by EPL+SHEAR
z=0.78   (+0.6355, +0.1375)  → deflected by the SIS *there*
z=1.6926 (+0.2336, +0.0719)  = source-plane position
    The SIS acts on the already-bent ray — the nonlinear coupling single-plane models cannot express. The facade returns only the last row, so downstream code sees "source coordinates" as usual.
  7. Image, PSF, point sources. MPLensImageAdapter.model routes kwargs_lens_light to the main plane's light plane and kwargs_source to the last one; the perturber plane is dark. kwargs_psf (live joint-PSF kernel) is threaded through MPLensImageWithPSF to the patched Numerics — joint PSF fitting works identically to single-plane. MPPointSourceModel solves the quad image positions through the full MP ray shooting.
  8. Time delays. facade.fermat_potential returns the effective Fermat potential: the absolute fiducial arrival time (133.7 d × main-plane term + 182.7 d × perturber-plane term) divided by TD_CONST · D_dt_fid = 77.2 d/arcsec². The unchanged single-plane code in prob_model.py:1899–1908 then computes Δt = TD_CONST · D_dt · Δφ_eff = Δt_fid · (D_dt / D_dt_fid). The fiducial D_dt cancels algebraically (verified to 4×10−15, see §6); the sampled D_dt carries all H0 information, exactly as before.

2. perturbers.py — catalog → model dicts (395 lines)

Everything upstream of the model: parse the perturber-finder JSON, get the positions into ALPACA's frame without orientation bugs, decide who is on which plane, and package plain-data dicts that survive the pipeline's rebuild-from-attributes pattern.

Dataclasses

Perturberperturbers.py:48

One catalog entry: id, ra_deg, dec_deg, pixel_xy, z, theta_E_cat, sigma_kms, flexion_shift_arcsec, notes. Two fields are filled later by prepare_perturbers: plane ("foreground" | "main" | "background") and center_x/center_y (ALPACA arcsec frame). The name property returns pert{id} — the prefix of every numpyro site for this perturber (pert5_theta_E, …).

PerturberSetperturbers.py:72

Parsed catalog: target metadata (ra0/dec0_deg, z_lens, z_source, pix_scale_arcsec, theta_E_main_arcsec) + the Perturber list + source path. z_lens/z_source from here (not the config!) feed the multi-plane geometry.

Loading & coordinate conversion

load_perturber_set(path)perturbers.py:85

Strict JSON parser. Every perturber must carry redshift.z and SIS_profile.theta_E_arcsec — missing values raise immediately rather than propagating NaNs into the model.

_tangent_offsets_arcsec(pset, perts)perturbers.py:136

Pure sky offsets from the target: u = ΔRA·cos(dec₀), v = ΔDec, in arcsec. No pixel convention yet — this is the raw input to both conversion routes.

_pixel_offsets_from_wcs_fit(pset, perts)perturbers.py:147

The rotation-proof route. Fits the affine sky→pixel map of the parent i2d image from the perturbers' own (RA/Dec, pixel_xy) pairs — 6 unknowns, needs ≥ 3 perturbers with pixel coordinates. The intercept is the target's pixel position. Catches rotation and parity flips that a naive North-up assumption would miss. Self-checks: fit RMS > 1 pixel ⇒ prints a warning and returns None (fallback route takes over). Perturbers without pixel_xy are mapped through the fitted transform; exact catalog pixels are kept where available.

_convert_positions(pset, perts, lens_center)perturbers.py:189

Fills center_x/y on each perturber: ALPACA's detected lens center is the anchor (it corresponds to the catalog target RA/Dec), plus the pixel offsets × pixel scale. Fallback when the WCS fit is unavailable: tangent-plane offsets assuming North-up/East-left (x = −u). Either way the perturbers_overlay plot in 01_input/ is the visual check — a flipped axis is obvious there.

Selection, plane assignment, packaging

prepare_perturbers(pset, lens_center, *, z_tolerance=0.01, …)perturbers.py:220

The gatekeeper. In order: (1) apply include_ids/exclude_ids whitelist/blacklist; (2) drop perturbers below min_flexion_shift_arcsec (None keeps all); (3) plane assignment — the line that decides everything downstream:

if single_plane or abs(p.z - pset.z_lens) <= z_tolerance:  p.plane = "main"
elif p.z < pset.z_lens:                                    p.plane = "foreground"
else:                                                      p.plane = "background"

(4) convert positions; (5) sort by redshift. Any non-"main" plane later flips make_lens_image into multi-plane mode. single_plane=True (config mode="single_plane") is the classic approximation: every perturber becomes a main-plane SIS and the forward model stays single-plane.

perturbers_to_model_dicts(perts, *, theta_E_max_factor=3.0, position_sigma_arcsec=0.3, fix_positions=False)perturbers.py:295

Converts Perturber objects into plain dicts (JSON/pickle friendly — they must survive the pipeline's stage-to-stage rebuild). Adds the prior hyperparameters the ProbModels consume: theta_E_max = 3 × theta_E_cat (Uniform prior upper bound), position_sigma (Normal prior width around the catalog position), fix_positions (freeze centers, θE stays free). These dicts are what ProbModel.perturbers actually holds.

perturber_inputs_from_config(pert_cfg)perturbers.py:325

Config → (PerturberSet, options dict); (None, None) when no catalog path is set (the default — the model is then byte-identical to the perturber-free pipeline). Shared by the pipeline runner and the postprocess replay so both build identical structures. This is also where H0_fid/Om0 leave the config (model.perturbers.cosmology, defaults 70.0 / 0.3).

plot_perturber_overlay(...)perturbers.py:354

Diagnostic: perturber positions + θE circles over the log-stretched data image, color-coded by plane. Off-image perturbers are clamped to the edge with an x marker so they stay visible. Always check this plot — it is the only defense against a silently flipped coordinate conversion.

3. multiplane.py — the translation layer (670 lines)

Everything multi-plane lives here. Constant first: TD_CONST = 2.8000503e-02 multiplane.py:54 — days per (Mpc·arcsec²), the same constant the single-plane time-delay factor uses (prob_model.py:1894). Keeping them identical is what makes the effective-Fermat trick exact.

Static geometry

MPGeometrymultiplane.py:71

A frozen bookkeeping record, built once at model construction:

plane_redshifts, main_plane_index, z_source mass planes, ascending; where EPL+SHEAR lives
plane_slotsfor each plane, which indices of the FLAT kwargs_lens list belong to it — e.g. [[0,1],[2]]. This list is the flat↔per-plane dictionary.
profile_listsherculens profile names per plane, aligned with the slots

build_plane_structure(perturbers, z_lens, z_source)multiplane.py:125

Groups profiles into planes. The flat kwargs order is fixed: [EPL, SHEAR] + one SIS per perturber in list order. Main-plane perturbers join the EPL+SHEAR plane; off-plane ones are grouped by identical redshift (one plane per unique z, ascending). Guards against a perturber tagged off-plane but sitting exactly at z_lens. extension point The one-slot-per-perturber mapping (plane_slots[j].append(2 + i)) is where "one profile per perturber" is hardcoded — a multi-profile companion (EPL+SHEAR) generalizes this to a running counter.

build_mp_geometry(geometry, mp_mass_model, H0_fid=70, Om0=0.3)multiplane.py:168

Fills the fiducial-cosmology numbers in place, using astropy (concrete floats, no JAX — these are static during inference): the eta matrix via herculens' MPMassModel.build_eta_matrix, the deflection scales, the per-plane time-delay prefactors, and D_dt_fid. Distance ratios are exactly H0-independent and only weakly Ωm-dependent — the standard TDCOSMO treatment (measured in §6).

The mass-model facade

_to_next_plane_convention(profile, kw, s)multiplane.py:217

Herculens' MP convention defines each plane's reduced deflection relative to the next plane back; ALPACA's parameters (and the catalog) are source-referenced — the standard single-plane meaning. This function rescales one profile's deflection amplitude by the static factor s:

SIS:   theta_E ← theta_E · s
EPL:   theta_E ← theta_E · s^(1/(γ−1))     # deflection ∝ θ_E^(γ−1)
SHEAR: gamma1/2 ← gamma1/2 · s

For HE 0435: s = 0.577 on the main plane, and herculens later multiplies deflections by η = 1.732 = 1/s during propagation — exact cancellation, so lens_theta_E in your chains means what it always meant. Raises NotImplementedError for unknown profiles rather than silently mis-scaling.

MPMassModelFacademultiplane.py:238

Speaks MassModel's API (ray_shooting, fermat_potential) with ONE flat kwargs list, over a herculens MPMassModel. It becomes lens_image.MassModel and prob_model._mass_model_for_rayshoot, so the time-delay and rayshoot likelihood factors work unchanged.

.split_kwargs(kwargs_lens)multiplane.py:253

The unfold: flat source-referenced list → per-plane list-of-lists in the MP convention, via plane_slots + _to_next_plane_convention. Skips the rescale when s = 1 (main-plane-only case). Called on every model evaluation; under jit the bookkeeping compiles away to constants.

._at_least_1d(x, y)multiplane.py:269

Workaround for an upstream bug: herculens' MPMassModel.ray_shooting mis-broadcasts scalar inputs (the (N+1, 1) eta slice turns them into (N+1, N+1)). Promotes to 1-D and remembers to squeeze the result back.

.ray_shooting(x, y, kwargs_lens)multiplane.py:277

Image plane → source plane with single-plane semantics: runs the herculens MP recursion, returns only xs[-1], ys[-1]. Consumers (rayshoot-consistency factor, diagnostics) never see the intermediate planes.

.arrival_time_days(x, y, kwargs_lens)multiplane.py:286

Absolute arrival time under the fiducial cosmology: mirrors herculens' MPMassModel.arrival_time but with the static eta matrix and the precomputed distance prefactors — no cosmology object in the jit-compiled hot loop. Per plane i: prefaci · (½|Δβi|² − ψi), summed.

.fermat_potential(x, y, kwargs_lens)multiplane.py:306

The effective Fermat potential: arrival_time_days / (TD_CONST · D_dt_fid), in arcsec²-equivalent units. Defined so that the existing single-plane code dt = TD_CONST · D_dt · Δφ yields exactly Δt_fid · (D_dt / D_dt_fid) — the standard rescaling that keeps ALPACA's D_dt parametrization intact. Reduces to the ordinary Fermat potential when only the main plane carries mass. D_dt_fid is a units choice, not an assumption (§6).

The lens-image subclass

MPLensImageWithPSF(MPLensImage)multiplane.py:323

Thin subclass of herculens' MPLensImage overriding exactly two methods, both to close upstream gaps — everything else (Grid, Numerics, convolution, adapt_source_coordinates, noise/χ² helpers) is inherited untouched.

.point_source_image(..., kwargs_psf=None)multiplane.py:328

Same as upstream but passes kwargs_psf down to ImageNumerics.render_point_sources — the live joint-PSF kernel must reach the point-source rendering too, not just the extended-light convolution.

.model(eta_flat, kwargs_mass, kwargs_light, ..., kwargs_psf=None)multiplane.py:350

Reimplements upstream MPLensImage.model with two fixes:

  • Live-PSF hook: upstream drops kwargs_psf; here it is threaded into re_size_convolve and point_source_image (honored by the patched Numerics in alpaca/patches/herculens_numerics.py exactly as in the single-plane model). Without this, joint PSF fitting silently uses the stale seed kernel in MP runs.
  • Plane-selective light evaluation: upstream MPLightModel.surface_brightness evaluates every light-carrying plane and only discards deselected rows afterwards — which IndexErrors when a deselected plane carries empty kwargs (e.g. source_add=False in the arc-mask non-source build). Here deselected planes are skipped before evaluation and replaced by zeros; per-plane brightness still comes from herculens' LightModel.surface_brightness. k-based deselection was no alternative: herculens routes single-profile LightModels to _surf_bright_single, which treats k as an integer index.

Note the jit constraint documented in the code: k_planes is a static argument — must be hashable (tuple/int/None) — and the mask indexing uses NumPy (python-int) indices because jnp index arrays would be tracers.

The LensImage-interface adapter

MPLensImageAdaptermultiplane.py:438

Presents LensImage.model()'s exact call surface over the MP stack. Marked by the is_multiplane = True class attribute — the flag the ~7 branch sites in the pipeline test with getattr(lens_image, "is_multiplane", False).

  • .MassModel is the MPMassModelFacade — every consumer of lens_image.MassModel.ray_shooting/fermat_potential works unchanged.

The builder — mirrors the single-plane make_lens_image internals; the already-constructed PSF/Noise/LightModel objects are reused, only the mass/lensing structure changes. 4. prob_model.py — priors, likelihood, kwargs (3340 lines)

The heart of the modeling layer. Three responsibilities: (1) model construction (make_lens_image), (2) two parallel numpyro model classes (ProbModel = analytic/Shapelets source, ProbModelCorrField = pixelated CF source), (3) shared flat-params ↔ herculens-kwargs helpers that keep every consumer (GD optimizer, NIFTy/nautilus likelihood modules, diagnostics) using the exact same ordering.

The ordering contract (module docstring, prob_model.py:33): the mass profile order is fixed everywhere as [EPL, SHEAR, SIS(pert_1), …, SIS(pert_n)], and the lens-light profile order as SERSIC (L1) [, SERSIC (L2)] [, SERSIC (L3)] [, MGE] [, UNIFORM sky — always last]. Every kwargs assembly — model(), params2kwargs(), sampler likelihoods — MUST use the same order, which is why the shared helpers below exist.

6. Exact vs. approximate — verified numerically

Run on the HE 0435 toy configuration with the actual MPMassModelFacade (July 2026, this branch):

The fiducial D_dt cancels at machine precision. Rebuilding the geometry with H0,fid = 60, 70 and 82.7 gives effective-Fermat differences identical to a fractional spread of 4×10−15 — bit-level identical predicted delays at any sampled D_dt. It is a units choice (it appears once in the numerator via the prefactors ∝ 1/H0 and once in the denominator via D_dt_fid ∝ 1/H0), not an assumption. The posterior on D_dt is anchored to the data, not to the fiducial.
The only real approximation: distance ratios frozen at Ωm = 0.3. Moving Ωm to 0.25 / 0.35 shifts the predicted delay by ∓0.16% / +0.18% — far below time-delay measurement errors (few %). In the single-plane limit even this vanishes identically. This is the standard TDCOSMO treatment of LOS structure; if ever needed, herculens' build_eta_matrix accepts a jax_cosmo cosmology, so sampling Ωm is a feasible extension.
Scale of the physics being added: in the same toy setup the 0.1″ SIS sitting ~1″ from image A changes that image pair's Fermat difference by tens of percent — orders of magnitude above the approximation error being accepted.

Also exact: the convention rescaling (cancels against η analytically), the ray shooting itself (herculens recursion, no approximation), and the single-plane limit of every facade method.

7. Contracts & gotchas

rulewhere enforced / where it bites
Flat kwargs order is law. [EPL, SHEAR, pert_1, …]; lens light per the ordering contract, sky always last. Assemble mass kwargs ONLY via kwargs_lens_from_params / sample_perturber_kwargs. The MP plane_slots are built against this exact order — a silent reorder mis-assigns profiles to planes.
Mirror-edit the twin classes. ProbModel and ProbModelCorrField duplicate sites, kwargs assembly and likelihood factors. Mass side is shared; light/likelihood edits must be made twice (e.g. lines 1755 ↔ 2889, 1893 ↔ 3018).
model() ↔ params2kwargs() must match. Sampling uses the former, every replay (plots, χ², warm starts) the latter. A site added to one only shows up as a subtly wrong replay, not a crash.
x64 is mandatory. NaN herculens' SIS profile (SIS → NIE with a tiny softening) returns NaN everywhere in float32. The pipeline enables jax_enable_x64 (runner.py:275), but any standalone script/notebook importing the model without it will silently NaN on perturber profiles.
k_planes is a static jit arg. Must be tuple/int/None (hashable) when calling MPLensImageWithPSF.model; the adapter always passes a tuple.
Scalars through the facade only. Raw MPMassModel.ray_shooting mis-broadcasts scalar x/y (upstream bug); MPMassModelFacade._at_least_1d works around it — call the facade, not the raw model.
Perturber positions: verify the overlay. The sky→pixel affine fit self-checks (RMS > 1 px ⇒ fallback + warning), but the perturbers_overlay plot in 01_input/ is the only human check against parity/rotation errors.
perturbers_meta is required for off-plane runs. make_lens_image raises without it; it carries z_lens/z_source (from the catalog) and H0_fid/Om0 (from config) into the geometry builder (data/setup.py:331).
