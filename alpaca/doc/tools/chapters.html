GuideOverview

ALPACA fits a strong-lens model to an image. The model has a mass model for the deflector (EPL + external shear, optionally multipoles, an external flexion, a broken power law and line-of-sight perturbers on their own redshift planes), parametric lens light (Sérsic profiles or a multi-Gaussian expansion), a source (shapelets, then a pixelated correlated field), a PSF that is refined together with the lens, and, for lensed quasars, the point images with their positions and time delays. Optional: stellar kinematics, several bands fitted with one lens model, correlated-field light for a perturber on its own plane. Everything runs in JAX, so every stage is differentiable and runs on a CPU, an NVIDIA GPU or an Apple GPU.

A run has two phases:

  1. Best fit (MAP): a staged gradient descent (§ The staged pipeline).
  2. Posterior: sampling from the best fit (NIFTy NUTS / geoVI, NumPyro NUTS or Nautilus; § Sampling). With time delays the model gives a time-delay distance and H0, blinded by default (§ Blinding).

Two kinds of lens are supported with the same pipeline: lensed quasars (point images, delays, cosmography) and galaxy–galaxy lenses (arcs or rings only, § Galaxy–galaxy lenses). The methods and their validation are in the paper: Krizic et al. 2026, arXiv:2609.04312. This page documents ALPACA 0.6.0; § What's new lists what changed since 0.4.

GuideInstallation

Install from the source repository into a fresh environment (Python 3.11 or newer). First install the exact herculens and jax-cosmo commits ALPACA was tested with, then ALPACA with the extra for your hardware.

git clone https://github.com/hkrizic/alpaca.git && cd alpaca
python3.12 -m venv .venv && source .venv/bin/activate && python -m pip install --upgrade pip
python -m pip install -r requirements-tested.txt   # herculens + jax-cosmo at the tested commits
python -m pip install -e ".[apple]"     # Apple Silicon GPU (MPS, float32)
# python -m pip install -e ".[cpu]"     # CPU, float64
# python -m pip install -e ".[gpu]"     # NVIDIA, Linux, CUDA 12   ([cuda13] for CUDA 13)
alpaca-device                           # shows which device JAX will use

  • Tests (with the dev extra): pytest tests/ -m "not slow and not gpu".

Guiderun_alpaca.py

The data paths, the approximate image positions (quasars) and the lens position sit at the top of run_alpaca.py; the science settings and the time delays sit in config.json.

IMAGE_PATH     = "/data/MYLENS/image.fits"
PSF_PATH       = "/data/MYLENS/psf_supersampled.fits"
NOISE_MAP_PATH = "/data/MYLENS/noise_map.fits"

# None = keep the config value; a value overrides the config for this dataset
PSF_OVERSAMPLE = None              # psf.input.oversample
PSF_STARRED_KWARGS_PATH = None     # psf.joint.seed_path
PSF_ERROR_MAP_PATH = None          # psf.input.error_map_path
LIKELIHOOD_MASK_PATH = None        # data.likelihood_mask_path
PERTURBERS_PATH = None             # mass.perturbers.path

IMAGE_POSITIONS = {"A": (-0.906, -0.937), "B": (-0.999, 0.656),   # arcsec from the lens; labels only:
                   "C": ( 0.406,  1.249), "D": ( 0.906, -0.531)}  # ALPACA re-detects the positions
REFERENCE_IMAGE = "A"              # likelihood.time_delays.reference_image wins when set
LENS_POSITION   = (0.0, 0.0)       # sub-pixel lens offset from the frame centre (arcsec)
TIME_DELAYS     = None             # None = use likelihood.time_delays from the config

# galaxy-galaxy lens: IMAGE_POSITIONS = None, TIME_DELAYS = None, light.point_sources.enabled = false

  • Delays. Since 0.5.2 they live in the config. With point sources on and likelihood.use_time_delays: true, the script stops when no delays are given.
  • No JSON given: the script falls back to default_config.py, the Python twin of the shipped config.json.
python run_alpaca.py config.json --fit-only                          # best fit only: a quick look
python run_alpaca.py config.json                                     # same folder: best fit reloaded, then sampling
python run_alpaca.py config.json --backend mps --precision float32   # Apple GPU
python run_alpaca.py config.json --output runs/variant_m4/           # another output directory

GuideTime delays

Paste the published delays into likelihood.time_delays, in days, with their 1σ errors: the n−1 delays of the images relative to one reference image.

"likelihood": {
  "use_time_delays": true,
  "time_delays": {
    "convention": "t_X - t_Y",
    "delays": {"AB": [-9.0, 0.8], "AC": [-0.8, 0.7], "AD": [-13.8, 0.8]},
    "covariance": "independent"
  }
}
Sign convention

The default "t_X - t_Y" is the convention of the COSMOGRAIL, H0LiCOW and TDCOSMO tables: "AB": [-9.0, 0.8] means tA − tB = −9.0 d, i.e. B arrives 9.0 d after A. Paste published numbers unchanged. Only the legacy single-label form {"B": [t_B − t_ref, σ]} (ALPACA ≤ 0.5.1, still accepted) has the opposite sign. The run log prints a table of the delays with the image that arrives later: check it once for every lens.

  • Keys: pairs "XY" or "X-Y"; values [value, σ] or [value, +σ, −σ] (symmetrised). Labels are the run's image labels.
  • Covariance (details): "independent" for at most n−1 non-redundant delays; "shared_curves" for a redundant table such as all six pairs of a quad (pairs that share a light curve are correlated); or a full matrix / {"correlation": R} from the measurement. Listing all pairs as "independent" is refused: it would count the data twice.
  • Closure. With "shared_curves" the listed delays must close (tXY + tYZ = tXZ) to within 1.5 × the largest pair error; a larger violation is a sign or label error and stops the run.
  • Diagnostic. 03_multistart/best_model/time_delay_ratios.png (best fit) and 05_posterior/plots/time_delay_ratios.png (posterior) compare the model's delay ratios with the measured ones, plus a delay-shape χ² with n − 2 degrees of freedom. DΔt cancels in the ratios, so both are safe in blinded runs.
  • Priors: likelihood.D_dt_prior (uniform 500–10000 Mpc by default; lower low for low-redshift lenses) and likelihood.kappa_ext_prior (external convergence, none by default).

GuideImage positions and astrometry

The measured positions of the quasar images constrain the mass model. Since 0.6.0 the default is the image-plane astrometry; write it explicitly in every config, as the shipped config.json does:

"likelihood": {
  "astrometry_mode": "image_plane",
  "sigma_ast": 0.005,
  "use_rayshoot_sys_error": false,
  "use_image_pos_offsets": false,
  "rayshoot_against_source_pos": true,
  "td_common_source": true
}
  • Image plane (astrometry_mode): one common source; the measured positions may differ from the model images by a Gaussian of width sigma_ast (5 mas) in the image plane, and every delay is evaluated for that one source. The likelihood is invariant under a mass-sheet transformation. In stage 1 the common source is the centre of the analytic host, so the quasar sits on its host's nucleus.
  • Source plane (the default up to 0.5.x): back-traced positions scatter with rayshoot_sigma plus a free floor. A fixed source-plane width carries artificial mass-sheet information; keep it for comparisons only.
  • Galaxy–galaxy lenses keep "image_plane": without at least two point images no astrometry term is built, neither in GD nor in sampling.
  • Old runs: a run folder without config/alpaca_provenance.json (written before 0.6.0) is reloaded with the old defaults ("source_plane", 0.003″) for the keys it omits, so it keeps its meaning.
  • Faint images next to bright light: bound the fitted positions with light.point_sources.position_bound_px.

GuidePerturbers

Nearby galaxies that deflect the light are listed in a catalogue JSON and switched on with mass.perturbers.path (or PERTURBERS_PATH in run_alpaca.py). GuideGalaxy–galaxy lenses

A galaxy–galaxy lens has arcs or a ring and no point images. The pipeline is the same; these settings differ:

Judge that the model is lensing, not painting: θE is not at a bound, the mass is centred on the light, the critical curve runs through the arcs, and the source is smaller than the arcs and dark away from its emission.

GuideThe staged pipeline

With the default joint PSF (psf.mode: "joint") the best fit is found in stages, each starting from the previous one. This is the recommended path for every lens.

stagewhat is fittedwhymain knobs
1 · shapelets
03_multistart/stage1_shapelets		 Mass, lens light (e.g. double Sérsic), a shapelet source and the live PSF; many random starts, annealed (noise inflated ×16 → ×1) and culled by successive halving, then the best are refined. A smooth source makes the multistart robust: it finds the right mass basin (for galaxy–galaxy lenses, the lensed instead of the unlensed solution). anneal, halving, refine, n_max
2 · lens-light refit
stage2_lens_light_refit		 The lens light alone (e.g. triple Sérsic) on the full frame, after subtracting the stage-1 source and point images; the arc annulus and the quasar cores are masked. The result starts stage 3. The full frame constrains the wings of the light profile and the sky, which the small cutout cannot. refit.profile, mask_path, mask_arc, init_cf_joint, sky "refit"
3 · CorrField joint
stage3_cf_joint		 Phase A grows a pixelated correlated-field source (and any perturber field) with everything else pinned; phase B fits source, mass, lens light and PSF together, until the plateau test or the step budget. The pixelated source captures the real source structure the shapelets miss; this is the model you judge and sample. loglogavgslope, num_pixels, arc mask, adam_steps, convergence
PSF-error b (quasars) After GD, the amplitude b of σ²eff = σ² + b²·PS² is fitted at the stage-3 optimum; it stays free in sampling (post_gd_free). Down-weights the quasar cores, where any PSF error dominates χ². use_psf_error_map, psf_error_b_max
warm start
04_sampling/warmstart		 The best fit is transferred exactly into the sampler's latent space and polished with L-BFGS on the posterior energy U = −log L + ½|ξ|². U compares models on the same data, mask and noise model; stop_after ends the run here. polish, stop_after
sampling
04_sampling, 05_posterior		 NUTS (and optionally geoVI) from the warm start. Uncertainties, the time-delay distance, H0. nifty.mode, target_accept (§ Sampling)
  • Stage 2 figures (stage2_lens_light_refit/plots/): 01_lens_light_fit.png (the full model and the light fit itself), 02_radial_profile.png (smoothness: excess over a smooth profile outside the arc band), 03_model_summary.png.
  • Stage 3 records: planes.png (every light plane, lensed and in its own plane), loss_curve.png, chi2_binned.png, cf_hyperparameters.json (the field hyperparameters in σ units; |z| > 3 = "railed"), and stage_summary.json with the stop reason and the improvement over the last window. A WARNING is printed when stage 3 ended on its budget while still improving.
  • The source grid and arc mask that stage 3 used are saved in 03_multistart/cf_prebuild/, so rebuilds and sampling use exactly the same model.
  • Use a shapelet-only model (psf.mode: "fixed", stages.cf_joint.enabled: false) only when you want one, for example as a quick systematic check; it can be sampled with NIFTy too.

GuideSource smoothness (cross-validation)

In a joint best fit, free hyperparameters of a correlated field run to rough fields: the source then fits noise and stops being interpretable. The railing report (cf_hyperparameters.json, printed at stage 3 and at the warm start) flags this. Fix the smoothness instead, chosen by how well the field predicts pixels it has not seen:

python -m alpaca.diagnostics.cf_cv run/ --field source --slopes -2 -2.5 -3 -3.5 --fluctuations 2.5
python -m alpaca.diagnostics.cf_cv run/ --field pert1  --slopes -2 -2.5 -3       # a perturber field
  • Random 4×4-pixel blocks of the field's region are held out (2 folds of 10 % by default). For every candidate (slope, fluctuations) the field restarts from its prior centre and is refitted on the training pixels to convergence (plateau test: --conv-tol 20 nats per --conv-window 2000 steps, at most --steps 20000); everything else stays at the run's best fit. The candidate map keeps the run's own priors (skip it with --no-map).
  • Results: run/06_cf_cv/<field>/results.json, table.txt, cv.png, ranked by the held-out χ² averaged over folds. Fits that were still improving at the budget are marked: a ranking of unconverged fits measures convergence speed, not prediction.
  • Pick the converged candidate with the lowest held-out χ², and fix it in the config with a tiny std, e.g. "loglogavgslope": [-2.5, 0.001], "fluctuations": [2.5, 0.001]. Then rerun the same config folder: finished stages whose settings did not change are reloaded.
  • With fixed hyperparameters, also set mean_intensity to about 0.1 × the noise; the default (70th percentile of the image) with a tight offset_std can leave a faint pedestal over the whole source grid.
  • Only χ² values are reported, so the tool is safe in blinded runs.

GuideRunning & budgets

The GD cost is set by the multistart (number of starts, anneal levels, Adam / L-BFGS steps), the refit steps and the CorrField steps. Typical settings:

budgetanneal levels · adam / lbfgshalving keeprefine toprefit · cf_warmstart · cf_jointlaptop (M-series)
quick[8,4,2,1] · 200 / 150[8,4,2,2]11200 · 1500 · 2500~5–15 min
standard[16,8,4,2,1] · 300 / 300[16,8,4,4,2]22500 · 4000 · 6000~30–60 min

halving.keep needs one non-increasing entry per anneal level; its first entry is the number of starts. Instead of a fixed stage-3 budget you can stop on a plateau with stages.cf_joint.convergence.

  • Resume. One output directory per variant. Re-running a configuration into a finished directory resumes it: a finished stage is reloaded when its fingerprint (the settings it depends on plus a hash of ALPACA's code) matches; a stage that must be redone is archived as stage…stale-<time>. Figures (alpaca/plotting/) and the multiband layer are not part of the code hash; any other code change, such as an upgrade, recomputes the stages once.
  • Provenance. Every run writes config/config.json (your input as typed), config/config_effective.json (every setting resolved) and config/alpaca_provenance.json (version, git commit, source hash, dependency revisions).
  • Clusters. Do not move, rename or reuse a run directory while a job writes to it. Slurm's --export splits values at commas. Keep the blinding key out of job logs (§ Blinding).

GuideJudging a model

Look at pictures before numbers. Start with 03_multistart/best_model/. A model is acceptable when:

  • the normalised residuals have no coherent structure: no arcs (source or mass), no rings or dipoles at quasar cores (PSF or astrometry), no quadrupole at the centre (lens light), no gradient (sky);
  • χ² is balanced by region (chi2_binned.png, diagnostics.txt): quasar cores, arcs, centre and outskirts. A global χ²red hides compensation, for example a component that fits the noise in one place (χ² well below the empty-sky level) while another region is not fitted;
  • nothing sits at a prior bound (diagnostics.txt for the best fit, boundary_flags.txt for the posterior), and no correlated-field hyperparameter is railed unless it is fixed on purpose;
  • stage 3 converged (no budget warning) and the warm-start polish reached its gradient tolerance;
  • the model is physical: γ about 1.8–2.3, mass and light aligned within about 10–20°, perturber masses consistent with their light, a galaxy-like source that does not touch the source-grid edge;
  • a different random seed lands in the same solution, and an extended model fits at least as well as the baseline it contains;
  • for quasars: the delay ratios agree with the measured ones (time_delay_ratios.png);
  • for the posterior: R̂ close to 1 and enough effective samples for every reported parameter (posterior_summary.json), no divergences, trees not saturating the depth limit.

Drizzled data have correlated noise: a good fit sits at χ²red ≈ 0.5–0.7. Judge structure and differences between models, not the distance from 1. python llm/tools/check_run.py run/ [--ref other_run/] writes a health card (χ² against a reference, railed b, large shear, perturbers at their caps, boundary flags, stage-3 and warm-start convergence, railed field hyperparameters).

GuideSampling

The default sampler is NIFTy in the whitened latent space ξ (required for correlated-field sources), started from the warm start.

The raw draws are dumped to nifty_nuts_raw.npz right after sampling and removed once the samples are saved, so a job that dies in post-processing can be recovered.
  • Several GPUs: NUTS chains can run in parallel on the devices (JAX_PLATFORMS=cuda,cpu, chain_method); geoVI records in geovi_run.json how many samples it actually used and whether it fell back from multi-GPU.
  • geoVI on a CPU can abort right after VI with LLVM ERROR: Unable to allocate section memory (the JIT exceeds Linux's vm.max_map_count, not the RAM). Run geoVI on a GPU.
  • Model comparison: bic.json counts the exported parameters and assumes independent pixel noise; compare it only between runs with identical source, PSF and export settings, and treat it as informational.

GuideStellar kinematics

A measured velocity dispersion constrains the mass profile and breaks the mass-sheet degeneracy together with the lensing. Switch it on with likelihood.use_kinematics:

"likelihood": {
  "use_kinematics": true,
  "kinematics": {"mode": "aperture", "observed_sigma": 222.0, "sigma_error": 15.0,
                 "aperture_kind": "square", "aperture_width": 0.55, "psf_sigma": [0.05],
                 "ds_over_dds": 1.72},
  "kappa_ext_prior": {"mean": 0.0, "sigma": 0.03}
}

(Illustrative numbers: use your measurement and your redshifts.)

  • Modes: "aperture" (one dispersion, spherical Jeans) or "resolved" (binned IFU Vrms from ifu_file) with dynamics "spherical" (constant, Osipkov–Merritt or generalised OM anisotropy) or "axisymmetric" (JAM; needs frame_pa_x_deg and frame_parity).
  • Required: ds_over_dds, and Sérsic lens-light components (the tracer).
  • λint, the internal mass sheet, is sampled by default and blinded whenever blinding is on; κext comes from likelihood.kappa_ext_prior.
  • Joint or importance sampling: by default the kinematics enter the sampled likelihood; importance_sample: true samples the lensing-only posterior and reweights it, marginalising the nuisances on grids.
  • Axisymmetric check: the JAM aligns the mass and every light component with light component 0; kinematics_axis_check.json records the offsets of the best fit and a warning is printed above 10°.

GuideMultiband

The mass, the perturbers, the time-delay distance and the image positions do not depend on wavelength; the lens light, the lensed source, the quasar fluxes, the PSF and the noise do. Multiband ALPACA fits several bands with one model for what is common and a free copy per band for the rest. The config is an ordinary config (the template every band starts from) plus a multiband block:

"multiband": {
  "reference_band": "F150W",
  "bands": {"F150W": {"data_dir": "data/F150W"},
            "F356W": {"data_dir": "data/F356W",
                      "overrides": {"stages.cf_joint.source.num_pixels": 64}}},
  "image_positions": {"A": [-0.906, -0.937], "B": [-0.999, 0.656], "C": [0.406, 1.249], "D": [0.906, -0.531]},
  "sharing": {"preset": "lensing"},
  "frame_offsets": {"enabled": true, "sigma_arcsec": 0.05},
  "joint": {"name": "joint", "polish": {"maxiter": 3000, "gtol": 1.0}, "sampling": false}
}
python run_multiband.py lens_mb.json --check                       # validate config, data and band geometry
python run_multiband.py lens_mb.json                               # every band, then the joint model
python run_multiband.py lens_mb.json --stage bands --bands F150W   # one band (bands can run as parallel jobs)
python run_multiband.py lens_mb.json --stage joint                 # joint model from the saved band fits
python run_multiband.py lens_mb.json --compare                     # compare sharing variants side by side
  • Bands run the ordinary pipeline in <output_dir>/bands/<band>/; the joint stage rebuilds them from disk, polishes the joint posterior energy with L-BFGS and optionally samples it with NIFTy-NUTS.
  • Sharing: presets lensing (default), achromatic_lens_light, independent (a consistency check); single groups can be overridden (groups).
  • Counted once: the delays (with the reference band), the astrometry and the kinematics (one tracer band, kinematics.tracer_band).
  • One sky frame: bands whose WCS is rotated (> 0.1°), mirrored or anisotropic relative to the reference are refused (resample them first); bands without a WCS are reported as unchecked. Small registration errors are absorbed by the frame offsets. All bands must use the same light.point_sources.fft_rendering and light.sky_psf. --check exits with an error after a CHECK! line.
  • Outputs in <output_dir>/<joint.name>/: REPORT.md, sharing.txt, joint_summary.json (blinding-safe numbers), the joint MAP (joint_map_params_full.npz with sealed blinded entries, joint_map_latent.npz), story figures 01_sharing … 07_frame_offsets, and posterior/ with sampling.
  • Limits: NIFTy NUTS only (no geoVI); the source is always per band; importance_sample kinematics is not supported; never run two joint jobs on the same run folder at once.

GuidePost-processing

alpaca.utils.postprocess reloads a finished run; the notebook analysis/alpaca_postprocessing_tutorial.ipynb walks through it. Every figure uses the ALPACA house style (alpaca.plotting.style.apply()).

from alpaca.utils.postprocess import (describe_run, load_posterior, load_best_fit,
                                      rebuild_prob_model, plot_model_summary, plot_corner_alpaca)
RUN = "/path/to/run"
describe_run(RUN)                          # stages, sampler, blinding at a glance
post = load_posterior(RUN)                 # blinded columns are deltas
plot_corner_alpaca(post)
built = rebuild_prob_model(RUN)            # the exact sampling model (pass lens_center=LENS_POSITION for
plot_model_summary(built, posterior=post, draw="best")   #  the run's own anchor; default: the MAP centre)
best = load_best_fit(RUN)                  # final GD parameters
  • plot_light_planes(prob_model, params, save_path=…): every light plane, lensed and in its own plane.
  • Delivery chain for collaborations: python -m alpaca.postprocessing RUN [--n 500000] [--params D_dt lens_theta_E …] [--out chain.h5] writes a KDE-resampled HDF5 chain; its information content is that of the raw draws, and it is blinded like the source posterior.
  • Health card: python llm/tools/check_run.py RUN [--ref OTHER_RUN] [--write].
  • The analysis app opens run folders in the browser.

GuideBlinding

For cosmography, blinding is on by default in the shipped config. Blinded quantities are stored as offsets from their posterior mean, so runs are compared through differences only. The scenario "previously_analyzed" blinds DΔt, H0, Dd, the radial mass slope(s), the Fermat-potential differences and the predicted delays; λint and a sampled κext are blinded as well.

  • Key: set one campaign key in ALPACA_BLINDING_KEY inside the job script, never in a config or a log. Without it a key is generated at run start and written to 05_posterior/samples/blinding_secret.key: move that file to whoever decides on unblinding.
  • Sealed GD files: the blinded entries of best_fit_params_full.npz (and the multiband joint_map_params_full.npz) are encrypted with the same key; best_fit_params.json has them stripped. Old plaintext files still load.
  • Safe diagnostics: delay ratios, χ² values, the cross-validation and the multiband summaries contain no blinded numbers.
  • Unblinding, once the collaboration decides: python -m alpaca.unblind <run> [--key-file FILE] (or --key, or ALPACA_BLINDING_KEY) writes an unblinded/ folder.
